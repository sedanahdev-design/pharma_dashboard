# لوحة متابعة التزام الصيدليات بالتصنيفات الدوائية

تطبيق ويب مبني على Django لمتابعة مدى التزام الصيدليات بالأصناف الدوائية
المستهدفة شهرياً. يقارن التطبيق، لكل تصنيف دوائي، الكمية المُباعة من الصنف
المستهدف مقابل الكمية المُباعة من الأصناف البديلة ضمن التصنيف نفسه، ليُظهر
بوضوح أين تنحرف الصيدليات عن القرار الشرائي ولماذا.

النسخة الحالية تعمل على أساس الكمية (العبوة) فقط دون قيمة مالية، إذ لا
تتضمن ملفات المصدر سعراً لكل صنف. يمكن إضافة عمود القيمة لاحقاً عند توفّر
قائمة أسعار.

## نظرة عامة على آلية العمل

- يرفع المستخدم شهرياً ملف المبيعات الموسّع (يتضمن عمود "الشروحات 5" الذي
  يحمل اسم التصنيف).
- يعرض التطبيق تحت كل عملية رفع جميع التصنيفات المستهدفة لذلك الشهر، مع
  إمكانية إضافة أو تعديل أو حذف أي تصنيف أو صنف مستهدف مباشرة من الصفحة
  وبتحديث فوري، أو استيرادها دفعةً واحدة من ملف "تارغيت + كاتيغوري".
- لكل تصنيف يظهر: الكمية الإجمالية، الكمية من الصنف المستهدف، نسبة
  الالتزام، تفصيل كل صنف مُباع ضمن التصنيف، وتفصيل حسب كل صيدلية.
- يتيح التطبيق تصدير تقرير Excel منسّق يشمل ملخصاً عاماً وتفصيلاً كاملاً
  وورقة مستقلة لكل صيدلية.
- عند إنشاء دفعة شهر جديد يمكن نسخ التصنيفات من شهر سابق ثم تعديل ما تغيّر
  فقط.
- يُنبّه التطبيق إلى الأصناف المستهدفة التي بيعت دون أن توسَم في عمود
  "الشروحات 5"، للمساعدة على تحسين توسيم الملف مستقبلاً.

## المتطلبات

- **للتشغيل عبر Docker:** Docker و Docker Compose فقط.
- **للتشغيل المحلي:** Python 3.12 أو أحدث.

## التشغيل عبر Docker (الطريقة الموصى بها)

من داخل مجلد المشروع، شغّل الأمر التالي لبناء الحاوية وتشغيلها في الخلفية:

```
docker compose up -d --build
```

بعد اكتمال البناء يصبح التطبيق متاحاً على العنوان `http://localhost:8060`.

- تُحفظ البيانات في وحدة تخزين Docker باسم `pharma_data` ولا تُفقد عند
  إعادة تشغيل الحاوية.
- لإيقاف التطبيق مع الحفاظ على البيانات: `docker compose down`.
- لحذف البيانات والبدء من جديد: `docker compose down -v`.

### متغيرات البيئة الاختيارية

تُضبط داخل ملف `docker-compose.yml`:

| المتغيّر | الوصف | القيمة الافتراضية |
|---|---|---|
| `DJANGO_SECRET_KEY` | مفتاح Django السري؛ يجب تغييره في بيئة الإنتاج | قيمة تجريبية |
| `DJANGO_ALLOWED_HOSTS` | النطاقات المسموح بها، مفصولة بفواصل | `*` |
| `SEED_DEMO` | تحميل بيانات تجريبية تلقائياً عند أول تشغيل | `1` |
| `GUNICORN_WORKERS` | عدد عمّال gunicorn | `3` |

## التشغيل المحلي (بيئة التطوير)

```
python -m venv .venv
.venv\Scripts\activate        # على Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo         # تحميل البيانات التجريبية (اختياري)
python manage.py createsuperuser   # لإنشاء حساب إداري للوصول إلى /admin/ (اختياري)
python manage.py runserver 0.0.0.0:8060
```

بعدها افتح `http://localhost:8060`.

## النشر عبر الإنترنت (Cloudflare Tunnel)

يعمل التطبيق محلياً على المنفذ `8060`، ويمكن ربطه بنطاق عبر Cloudflare
Tunnel دون فتح أي منفذ على الراوتر:

1. ثبّت أداة `cloudflared` على الجهاز نفسه الذي يشغّل Docker.
2. لتجربة سريعة برابط مؤقت: شغّل نفقاً مؤقتاً موجّهاً إلى
   `http://localhost:8060` للحصول على رابط `trycloudflare.com` فوري.
3. لنفق دائم بنطاق خاص: سجّل الدخول بحساب Cloudflare، أنشئ النفق واربطه
   بالنطاق المطلوب، ثم شغّله موجّهاً إلى `http://localhost:8060`. بعد ذلك
   أضِف النطاق إلى `DJANGO_ALLOWED_HOSTS` في `docker-compose.yml` وأعد
   تشغيل الحاوية.

تفاصيل تثبيت `cloudflared` وأوامره في التوثيق الرسمي:
<https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/>

## هيكل المشروع

| المسار | الوصف |
|---|---|
| `config/` | إعدادات Django والمسارات الرئيسية |
| `tracking/` | التطبيق الأساسي: النماذج والقوالب ومنطق الحساب والاستيراد والتصدير |
| `tracking/services/parsing.py` | قراءة ملفَّي "موسّع" و"تارغيت + كاتيغوري" بمرونة |
| `tracking/services/reporting.py` | حساب الكمية المستهدفة مقابل البديلة لكل تصنيف |
| `tracking/services/export.py` | توليد تقرير Excel المنسّق |
| `tracking/management/commands/seed_demo.py` | أمر تحميل البيانات التجريبية |
| `sample_data/` | ملفات مبيعات تجريبية تُستخدم في `seed_demo` فقط |
| `templates/` | القوالب المشتركة |
| `Dockerfile`, `docker-compose.yml`, `docker-entrypoint.sh` | ملفات التشغيل عبر Docker |

## آلية احتساب الأرقام

لكل سطر في ملف المبيعات الموسّع:

1. إذا كان اسم الصنف مطابقاً لأحد "الأصناف المستهدفة" في أي تصنيف، تُحتسب
   كميته ضمن **المستهدف** لذلك التصنيف، حتى لو لم يكن موسوماً في عمود
   "الشروحات 5".
2. وإلا، إذا كانت قيمة عمود "الشروحات 5" تطابق اسم تصنيف معرّف لذلك الشهر،
   تُحتسب كميته ضمن **البديل** لذلك التصنيف.
3. غير ذلك، لا يدخل السطر في أي إحصائية ويُعدّ صنفاً غير متتبَّع لذلك الشهر.
